Interpretation and limits
- Backup mode (admin+2f4) is a simulation stall; disconnecting is admin+2ed.
  Neither alone identifies a replacement host. Original role is remembered
  when entering each match.
- Automatic timeout voting is optional, off by default, starts after 20 seconds,
  and is limited to three attempts with 30-second spacing.
- The native in-menu exit in 1.3.72 may have the same leave reason as a crash
  without sending ClientDisconnectRequest. It may therefore start recovery.
  Explicit received requests and reason 11 kicks are still excluded.
- Only the existing, precisely verified null-player guard is applied; this
  experiment does not skip assertions or suppress graphics/driver failures.
- Earlier failed attempts (startup delay, Steam relaunch during startup and
  a premature scripted host launch) are not counted as successful tests.
- The recorded runs used an upstream command example that displayed lobby
  capacity 5860, although only two peers joined. Inspection of the 1.3.72
  command at RVA 13f84f and the VM lobby revealed the first numeric argument
  is capacity. The scripts now pass 2 there; native plugin/launcher unchanged.
  This script-only correction was compiled but not replayed end-to-end.

Still requires multiplayer acceptance
- Remote-player recovery over the Internet/Steam, different network conditions.
- Simultaneous drops, repeated long sessions, large saves and more than two peers.
- Explicit original-player identity/slot reclamation, observers and replay checks.
- State checksum comparisons at matching simulation ticks after resuming.
  Identical transferred saves and clean short logs are not proof of long-term sync.
- Seamless joining into an active simulation and automatic host migration.
