# Reliability features in 0.5.0

1. Launcher updates retain `.previous` next to the executable. An independent hidden PowerShell helper uses .NET file/process APIs, verifies the staged SHA-256, atomically replaces the EXE, starts it, and waits up to 60 seconds for a per-attempt window acknowledgement. A failed process or missing acknowledgement restores and restarts the previous EXE. The failed hash is blocked until a different update is published. This protects updates initiated by 0.5.0 or later; older launchers keep their original updater when upgrading to 0.5.0.
2. Patch installation snapshots changed/deleted files and the previous install state before modifying game files. Journals survive interruption. Startup recovers an unfinished transaction before proceeding. Settings > Recovery restores the previous installation. No saves are intentionally added to patch packages. Backups are validated before restoring. Disk permission or backup damage errors stop restoration with an error.
3. Components and Multiplayer accept the existing PAW configuration code. Parsing validates all fields and unsupported combinations before applying settings. Local game path and launcher language are preserved. Files are reconciled by Install or Launch.
4. Multiplayer reads actual managed files, the base EXE, DLLs, RWD archives and extra TGI data in the game folder, and the same file types in the game's own `Documents\Kohan2\data` depot (`%USERDATA%/data/` in `autoexec.txt`, listed as `%USERDATA%\data\…`). That depot outranks the game folder and the game's join check ignores it; its `User`, `Save`, `saves`, `CampaignSave`, `DynamicCampaignSave`, `Films`, `Maps`, `RandomMap`, `Screenshots` and `synclogs` folders hold the player's own files and are skipped, so an install with no hand-installed game files there keeps its earlier fingerprint. Its fingerprint includes module versions/hashes, channel, selected EXE and settings. Copy and Compare recheck files; green requires no verification errors and an exact peer fingerprint. This is an exact-installation comparison, not a guarantee against simulation bugs. Localization is deliberately included and can produce conservative mismatches between compatible translations. Files in other user-defined depots are outside this fingerprint.
5. A working configuration is recorded after a game window remains running for 20 seconds. The observer follows the patched launcher's game process within the game directory. Restoring working settings selects the original signed release and applies it on Install/Launch. A working startup does not certify match stability.
6. Launcher/game session records identify unclean exits and known nonzero exit codes. Unknown game exits after closing the launcher or restarting the PC are labelled unconfirmed, not asserted to be crashes. Notifications offer diagnostics; diagnostics also work when no game installation is found and include launcher errors/updater logs. Nothing is sent automatically.
7. Launch verifies the original EXE against the signed game requirement plus managed executables, DLLs, INI and startup files. Full verification remains in Settings. Failed checks prevent launch.
8. Downloads show current package, bytes, speed and ETA. Pause preserves partial bytes. HTTP Range resumes them; a server returning a full response replaces rather than appends. Invalid ranges, sizes and SHA-256 are rejected. Network interruptions are retried, while user cancellation stops promptly. Final bytes always require the signed hash.
9. Changelog tabs show an unread dot per category (patch is channel-specific). Clicking a tab marks the currently advertised history as read.
10. Settings selects Latest or a previously verified release. Beta history references contain separately signed manifests; historical files are reverified before use. A pin applies to patch data, never to launcher security/reliability updates. A previous release must still have downloadable assets or cached packages.

## Validation

The test runner covers configuration round-trips and invalid inputs, durable and explicit rollback (including deleted files and damaged backup refusal), exact file fingerprints, critical startup file validation, signed historical release rejection, HTTP Range/ignored Range/cancellation. `--self-update-fixtures` runs the actual recovery helper against healthy, crashing and non-acknowledging standalone fixtures, including paths with Cyrillic characters, spaces, an ampersand and an apostrophe.

Real package transition validation installs Beta, switches to Stable, checks removal of color files, then rolls back and verifies the restored Beta hashes. UI previews and a separately published WPF startup smoke check are additional release gates.

The 0.5.0 release passed 122 automated assertions, all three real self-update helper scenarios, the real-package Beta/Stable/rollback transition, and WPF startup checks both with adjacent configuration and as a standalone EXE using embedded configuration. These checks do not replace a manual multiplayer game test.
